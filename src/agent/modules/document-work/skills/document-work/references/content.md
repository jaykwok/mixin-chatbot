# 内容规划与交付检查

按读者要作出的判断安排内容。以下是参考问题，可合并、调整顺序或省略无关项。

| 场景 | 内容应回答的问题 | 常用结构 |
| --- | --- | --- |
| 售前 | 客户要解决什么问题？资料中的哪些能力适用？如何部署？有哪些前提、限制和待确认事项？ | 客户背景与目标 → 方案与组件 → 部署与实施 → 边界与待确认 |
| 交付 | 范围和责任是什么？实施前需要什么？怎样操作、验证、验收和回退？ | 范围与责任 → 前置条件 → 实施步骤 → 验收用例 → 回退与运维衔接 |
| 售后 | 现象及影响是什么？有哪些日志或复现证据？哪些原因已证实、哪些只是推测？处理后怎样验证？ | 现象与影响 → 证据 → 已证实原因 / 推测 → 处理与验证 → 后续建议 |

多资料成稿时，先用 `document_inspect(outline)` 看每份资料的页面或章节，在临时目录记下“目标章节或页面 / 来源文件与位置 / 沿用、修改或新增 / 待确认项”。这是工作记录，不需要用户逐行审批。查询和文件提取仍使用现有资料索引及 `document_extract`。

## 内容取舍

- 复用内容要检查适用产品与版本、单位、术语、前置条件、旧客户名称和项目承诺。生成的客户方案是本次交付物，不因此成为新的正式产品依据。
- 材料引用了未提供的报价表、版本说明或其他原件时，标明缺少的依据，不把转述当成已核验。
- 早期方案、发布计划和后续版本说明存在差异时，按实际适用条件表达，保留需要确认的事项。
- 把“零泄露”“全面覆盖”一类绝对表述改为具体覆盖范围与验证条件。
- 营销材料中的联系人、内部价格、省份专项政策不进入客户文件，除非用户明确要求。

## 交付前检查

1. 修改范围：只改了用户指定的部分；未要求的段落、页码、页眉页脚未变。
2. 结构：组装后无内容重叠、缺失衔接、编号断裂；PPT 页码连续；Word 列表编号连续。
3. 遗留：无模板占位文字、示例文字、旧客户名、内部备注；`build.attention` 列出的页已看图。
4. 版式：实际渲染图上无溢出、遮挡、断表、图片缺失；渲染字体可能与客户 Office 不同，给文字留余量。
5. 说明：交付时列出主要来源、实际改动和待确认项；仅凭文件能打开或文字提取成功，不能声称版式已检查。
