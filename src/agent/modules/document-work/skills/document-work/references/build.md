# 用 Markdown 在模板上生成内容

`document_build` 与 `document_compose` 的 `content` 项都接受同一种 Markdown。内容由你写，排版由工具按模板完成：Word 继承页面设置、页眉页脚、主题字体和样式；PPT 继承母版和版式，并从模板样例页推断标题位置、字体、字号与颜色。

## Markdown 约定

| 写法 | Word | PPT |
| --- | --- | --- |
| `# 标题` / `## 标题` | Heading 1 / Heading 2 | **起新页**，标题写入页首 |
| `### 标题` | Heading 3 | 页内小标题（加粗） |
| 段落、`**粗体**`、`*斜体*`、`` `代码` `` | 正文样式 | 正文文本框 |
| `- 项目`、`1. 项目`、缩进两级 | List Bullet / List Number | 原生项目符号与编号 |
| 表格（`\|` 语法，支持 `:--` 对齐） | 表格样式，表头跨页重复 | 原生表格，表头着色；行数多时自动续页 |
| `![说明](路径 "width=8cm")` | 居中图片 + 图注（Caption） | 图片；与文字同页时自动左右分栏 |
| `> 引用` | Quote 样式 | 缩进段落 |
| 代码块 | 等宽、浅底 | 等宽文本 |
| ```` ```mermaid ```` 代码块（流程图，子集见 [slides.md](slides.md#带分支的流程图)） | 自动分层布局后插入 PNG（需中文字体） | 原生形状流程图，画在标题与引导文字之下 |
| `---` 或 `<!-- 分页 -->` | 分页 | 强制换页 |
| `<!-- notes: 讲稿 -->` | 忽略 | 写入当页备注 |
| `<!-- cards -->` `<!-- flow -->` `<!-- layers -->` `<!-- timeline -->` `<!-- cycle -->` `<!-- pyramid -->` `<!-- stats -->` `<!-- plain -->` | 忽略 | 指定当页图示，见下文 |

图片路径可以是本群 workspace 中的产品图（相对路径或绝对路径）、`document_images` 提取出的素材，也可以是你先在 tmp 中截取或生成的图片；支持 png / jpg / gif / bmp / tiff，单张不超过 32 MiB。不存在或格式不支持的图片会被跳过并在 `warnings` 中说明。

不要使用 HTML、脚注、数学公式或嵌套表格；不要为了排版在文字里补空格或全角空格。

## PPT 参数

- `template`：任意本群 PPT，通常选产品介绍或客户方案原件，它的母版和标题风格会被沿用。没有合适模板时省略，用默认 16:9 版式。
- `keepSlides` + `sequence`：保留模板的封面、目录、封底等页，并指定新页插入位置。例如 `keepSlides: [1, 45]`，`sequence: [1, "content", 45]`。
- `styleFrom`：模板页较杂时，指定几页内容页作为标题样式与内容区域的推断依据。
- `title` / `subtitle` / `cover`：有 `title` 时默认生成封面页。产品方案类 PPT 的封面元素通常画在第 1 页上而非版式里，此时生成的封面会是白页；应改用 `keepSlides: [1]`、`cover: false`，再用 `document_patch` 改封面上的客户名或标题。大纲中首页 `chars` 很少且版式名含“标题幻灯片”，一般表示版式自带封面设计，可直接 `cover: true`。

结果中的 `build.layouts` 列出本次新生成页中实际排成图示的页（`mode` 为 cards / timeline / flow / layers / pyramid / cycle / stats / flowchart 和分段数），`build.attention` 列出自动缩小字号、自动续页、排成图示或图示退回普通版式的页码和原因，这些页需要重点看图。描述新页时只以 `layouts` 为准；`keepSlides` 保留的模板页不在其中。每页正文超过约 8 行时就应拆成两个 `##` 节，而不是依赖自动续页。

## PPT 版面：卡片、流程、架构等图示

打算做成图示的页，在 `##` 标题后写注释指定；下表的自动识别只在没写注释时兜底，条件不满足会退回普通版式并在 `attention` 里说明原因。分段来自 `###` 小节、列表项（“标签：说明”）或箭头串。

| 写法 | 结果 |
| --- | --- |
| 一页内 2–6 个 `###` 小节，每节不超过约 6 行、220 字，且没有表格、代码 | 多栏卡片（≤3 个一行，4 个 2×2，5–6 个 2×3），`###` 为卡片标题，小节前的段落作为页首引导句 |
| 上述 `###` 名称都以“层”结尾，如“应用层 / 平台层 / 基础设施层” | 分层架构图：每层一条横带，层名在左，列表项成为带内的小方块 |
| 一段“调研 → 设计 → 部署 → 验收”（`→`、`->`、`=>` 分隔，3–8 项，每项 ≤14 字） | 箭头流程图，每步一个箭头形 |
| 3–6 项列表，每项以“第一阶段：”“2026年3月：”“Step 1：”这类阶段或时间标签开头（标签 ≤24 字），每项 ≤120 字 | 横向时间轴，冒号前为节点标题，冒号后为说明；嵌套子项成为节点下的要点 |
| 2–5 项列表，每项标签是数字加简短单位，如“135000+：公网暴露实例”“82 个国家：分布范围”“24h：响应时间” | 数字指标：大号数字 + 说明 |
| `<!-- cards -->` `<!-- flow -->` `<!-- layers -->` `<!-- timeline -->` `<!-- stats -->` | 强制对应图示（2–8 段，指标 2–5 段） |
| `<!-- cycle -->` | 循环图：3–8 个节点绕环排列，箭头首尾相连 |
| `<!-- pyramid -->` | 金字塔：2–6 层，第一个 `###` 在顶端最窄 |
| `<!-- plain -->` | 保持普通标题 + 列表版式 |

**图标**：标签开头的表情或符号（“🔍 资产识别”“⭐ 重点”）会变成图标徽标，卡片和流程图放在标题上方，时间轴放进节点，循环图和指标放在文字前；`###` 小节里放一张图片（`![](图标.png)`，可来自 `document_images`）则以该图片为图标。图标不是必需的，产品资料没有对应图片时用表情即可，不要为凑图标编造图片路径。分层、金字塔、循环、指标不放图片图标：小节里有图片时这几种会退回普通版式并提示，需要图片就改用卡片、流程或时间轴。

注释写在该页 `##` 标题之后。文字装不下（最小 14pt）时会退回普通版式并在 `attention` 中说明，因此每段写短句，不要塞整段解释；标签（冒号前的部分）保持在 12 字以内，补充说明放冒号后；分层图每层最多 12 个小方块，超出改为文字说明。最后一个 `###` 小节之后的段落会算进该小节，页面总结句要么放在第一个 `###` 之前作为引导句，要么另起一页。Word 忽略这些注释与图标约定，按标题和列表输出。

图文同页时，图片默认放在文字右侧；宽图（宽高比 ≥1.5，如架构图截图）配一两句说明时改为上文下图、图占整行。截取架构图时把 `box` 收紧到图示本身，不要带上原页标题和正文。

## 从资料中取图

`document_images` 从本群 PDF、PPT、Word 中把内嵌位图提取到 tmp，返回每张图的页码、像素尺寸和在页面中的位置比例（`box`，左上角为原点），重复出现的背景和 logo 只保留一次并标出 `pages`，整页大图标为 `fullPage`。返回的 `path` 可直接写进 Markdown 的 `![说明](path)`。

架构图常由多个形状或矢量图组成，无法作为单张图提取；先 `document_render` 看页面，再用 `crops: [{ page, box: [x0, y0, x1, y1] }]` 按比例截取该区域（PDF 直接可用，PPT/Word 需要 LibreOffice）。截图是位图，放大有限，宜用 `width=` 控制在页面一半以内。产品资料中的示意图属于正式资料，引用时保持原意，不要拼接改动。

## Word 参数

- `template`：任意本群 Word，通常是同类正式文档或历史方案。工具清空其正文，保留节设置、页眉页脚、样式与主题；如需保留原正文的一部分，用 `document_compose` 的 `start,end` 复用正文块，再跟一个 `content` 项。
- `title` / `subtitle`：写入 Title / Subtitle 样式；模板没有这些样式时退回加粗大字。
- 页眉页脚随模板保留，包括其中的文档名和页码域；需要改页眉文字时对成品用 `document_patch`（含页码域的段落会被拒绝，改相邻段落或用脚本）。

## 与选编组合

```json
{
  "filename": "客户方案.pptx",
  "items": [
    { "source": "产品介绍.pptx", "slides": [1] },
    { "content": "## 客户需求与交流目标\n- 需求一\n- 需求二" },
    { "source": "产品介绍.pptx", "slides": [35, 42] },
    { "content": "## 实施安排\n| 阶段 | 内容 | 产出 |\n|---|---|---|\n| 试点 | 一个部门 | 审计报告 |" },
    { "source": "产品介绍.pptx", "slides": [45] }
  ]
}
```

第一项必须是文件，它决定母版与尺寸；`content` 项按它的样式生成。Word 同理，第一份来源提供页眉页脚和样式。

## 需要写脚本的情况

和原页对齐的图示、卡片内嵌截图、多张图并排等，工具不会自动生成。先用上述方式得到成稿，再调用 `document_environment`，用 `uv run --no-project --python "$PI_PYTHON" "$PI_USER_TMP/adjust.py"` 对副本中的具体页做布局调整；[slides.md](slides.md) 有 python-pptx 起点和流程图脚本，[word.md](word.md) 有 python-docx 起点。调整后重新 `document_render` 核对。
