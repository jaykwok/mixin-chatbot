# 文档加工模块完善方案（2026-09-19）

[设计说明](document-tools.md) · [开发指南](development.md) · [群聊使用](usage.md#文档怎么提需求)

本方案基于三方面输入：现有模块代码与回归；2026-09-16 用真实产品资料完成的三份成品试验（`tmp/document-trial`）；Anthropic 公开 skill 与常见开源库的做法。目标是让"复用产品资料 + 在资料基础上新增内容"成为一次工具调用即可完成的确定性操作，而不是依赖模型临场编写排版脚本。

## 问题

| 现象 | 影响 |
| --- | --- |
| 新增章节或页面必须由模型现写 python-docx / python-pptx 脚本，再渲染看图迭代 | 试验中最耗时的环节；弱模型容易产生版式错误、遗漏中文字体、文本溢出 |
| 真实模板（电信模板、产品介绍 PPT）的版式没有占位符，标题是普通文本框 | 通用的"填占位符"方案无效，必须从样例页推断标题样式与内容区域 |
| `document_inspect` 只返回逐段文字，PPT 选页要通读所有段落 | 40 页以上的方案选页成本高，且容易漏掉图片页 |
| 复用页面和新增页面要分别生成再组装，母版重复导入 | 步骤多，产物体积大，来源记录分散 |
| skill 指南依赖示例脚本，没有明确的内容格式约定 | 不同模型执行路径差异大，交付质量不稳定 |

## 借鉴与取舍

| 来源 | 借鉴 | 不采用 |
| --- | --- | --- |
| Anthropic docx/pptx skill（专有许可，不复制内容） | 先看缩略图和大纲再选页；结构操作先于内容修改；组装后清理不可达部件；交付前检查遗留占位文字、旧客户名和溢出；模板字体与渲染字体差异要留余量 | 其 docx-js / pptxgenjs 从零生成路线（本项目要求沿用资料自身版式）；其脚本与素材 |
| md2pptx、pandoc 一类 Markdown 转文档工具 | 用 Markdown 作为模型输出内容的中间格式，由确定性代码负责排版 | 引入新依赖；本项目用已有 marked 解析、python-docx / python-pptx 渲染 |
| pptx-automizer、docxcompose（已用） | 跨文件复用页面与章节 | — |

## 方案

### 1. 新增 `document_build`：按 Markdown 在模板基础上生成 Word / PPT

- 输入：`format`、`content`（Markdown）、可选 `template`（本群任意 Word / PPT，作为样式与母版来源）、`title` / `subtitle`、PPT 的 `keepSlides`（保留模板的封面、封底等页）。
- Word：以模板文档为底（页面设置、页眉页脚、样式、主题字体全部继承），清空正文后按 Markdown 生成标题、段落、多级列表、表格（表头跨页重复）、图片与图注、引用、分页。没有模板时使用清晰的中文默认版式。
- PPT：继承模板母版与版式；从模板样例页自动推断标题文本框的位置、字体、字号、颜色，以及内容区域；`#` / `##` 生成新页，段落与列表进入正文区，表格生成原生表格，图片与文字自动左右分栏；按字号与区域估算行数，超出时自动续页或适度缩小字号，并在结果中标出需要重点检查的页。
- Markdown 方言在 skill 中明确约定，只使用标题、段落、粗斜体、列表、表格、图片、引用、分页和备注注释。
- 结果与现有工具一致：输出到用户 tmp、返回摘要与来源记录、`visuallyReviewed: false`。

### 2. `document_compose` 支持内联新增内容

`items` 可以混合 `{ source, slides }` / `{ source, start, end }` 与 `{ content }`。内联内容以第一份来源为模板生成，PPT 直接追加到同一母版下，避免重复导入；Word 以第一份文档的样式生成后追加。一次调用即可得到"封面 + 复用页 + 新增页 + 复用页"的成品和完整来源记录。

### 3. `document_inspect` 返回大纲与版式信息

- PPT：每页标题（顶部文字推断）、文字量、图片 / 表格 / 图表数量、是否隐藏；版式列表；推断出的标题样式。
- Word：标题层级与正文块位置、可用样式、页面设置。
- 响应中直接给出截断后的大纲，完整内容仍在清单文件中，方便选页和选章节。

### 4. skill 重写

SKILL.md 按"局改 / 选编 / 在资料基础上新建 / 检查交付"组织，正文短、指令明确；`references/build.md` 记录 Markdown 约定与模板行为，`word.md`、`slides.md` 保留编辑要点，`content.md` 保留业务内容与交付检查清单，并补充遗留占位文字、旧客户名、绝对承诺、溢出等检查项。

### 5. 回归与文档

- 真实文件回归增加：基于夹具模板生成 Word / PPT、含图与表格的内联组装、大纲输出、模板标题样式推断、溢出续页。
- 更新 `docs/document-tools.md`、`development.md`、`usage.md` 与 README 的工具描述。

## 不做的事

- 不引入 OCR、不处理旧 .doc / .ppt。
- 不承诺动画、SmartArt、外部链接无损。
- 不把 Markdown 方言扩展成排版语言；复杂版面仍由模型在固定环境写针对性脚本。
